# Texts in English and German

Owner decision: OnPath is English + German. The texts follow the phone's language (German phone → German,
any other → English); Settings → Diagnostics → Developer tools can fix it to **System / English / Deutsch** (kept across
restarts, `data/AppLanguage.kt`). Diagnostics shows the active language.

Not translated (stay English on purpose): Settings → Diagnostics and Developer tools, the problem log
(`debug/Problems`, read in bug reports), log lines, map labels (German / local names from OpenStreetMap), release notes.

## Where the texts are
- `strings/` – a small Kotlin Multiplatform module holding the texts as **Compose Multiplatform resources**
  (`docs/design/multiplatform.md`: the texts do not move again when an iPhone version comes; Compose resources need the
  Multiplatform plugin, which is why they are not in `app/`).
- `strings/src/commonMain/composeResources/values/strings_<area>.xml` = English (default),
  `values-de/strings_<area>.xml` = German. One file per area (`common`, `activity`, `plan`, `navigate`, …); keys start
  with the area (`plan_…`, `nav_…`) and are lower_snake_case. Generated accessors: `com.onpath.strings.Res.string.<key>`,
  `Res.plurals.<key>`.
- `tools/i18n/meta/strings_<area>.json` – per key: area / screen, context (when shown, what the placeholders are),
  `max` length where the UI is tight, priority 1–3 and confidence (sicher / bitte prüfen / Zweifel + `doubt`). The review
  sheet is built from it.
- `tools/i18n/glossary.tsv` – fixed terms EN → DE.

## Using a text in code
- Compose: `Text(str(Res.string.plan_save_route))`, `plural(Res.plurals.plan_points, n, n)`.
- Anywhere else (view model, service, notification, pure helpers like `RouteWarnings`): `Txt.s(Res.string.key, args…)`,
  `Txt.p(Res.plurals.key, count, args…)` – plain calls, no coroutine.
- Imports: `import com.onpath.strings.*` (Res, Txt, str, plural and the generated keys).
- Placeholders: only `%1$s` / `%2$d` (Compose resources). Numbers are formatted first and passed as text:
  `Format.distance(m)` ("12,5 km" in German), `Format.number(v, 1)`; units stay km / m / h / min in both languages.
- Whole sentences, never glued pieces: `"New route for %1$s – check it"`, not `"New route for " + name + " – check it"`
  (German word order differs). Lists joined with " · " are fine.
- Plurals for counts: `<plurals>` with `one` and `other`. The German `one` form may leave the number out ("Entfernt den Punkt davor").
- German must keep every placeholder, except keys listed in `StringFilesTest.germanMayOmit` (the hiking chip is "T2" in German: "Wandern · T2" cut the route's distance).
- Write `'` and `"` plainly (no `\'`), a `%` needs no escaping, `\n` is a line break.
- Enums with a user text keep a resource and expose the text as a property (`Activity.label` → `Txt.s(labelRes)`);
  the enum name stays the stored form.
- A missing key throws in tests and is a problem log entry (the key is shown) in the app.

## German style
- "du", friendly and factual; short; no marketing words, no superlatives, no exclamation marks.
- Buttons in the infinitive ("Speichern", "Navigation starten"), hints and questions in du-form ("Prüfe die Fahrzeiten").
- Decimal comma ("12,5 km"); times as on Alpine signposts: "1 h 05 min" (same as English).
- Terms from `tools/i18n/glossary.tsv`.

## Tests
- Unit tests and Paparazzi run in English (Gradle sets `user.language=en`); they read the XML files directly
  (`onpath.stringsDir`), so a missing key fails the test.
- `strings/…/StringFilesTest`: every English key has a German text with the same placeholders, plurals have `one` and
  `other`, no Android-only syntax.
- German screenshots: `GermanScreenshotTest` (plan sheet, activity picker, route hints, settings) to check lengths.

## Review round trip (owner sheet)
The review is a set of Google Sheets in the owner's Drive (External-Docs → "Übersetzung EN–DE (Review 2026-10-26)": background + glossary + priority 1, then priority 2a / 2b / 3 – the Drive connector creates one tab per file). Download each as CSV or xlsx and run `import` on each file.

`tools/i18n/i18n.py`:
- `export` → CSV + xlsx (columns Key | Priorität | Sicherheit | Bereich | Kontext | English | Deutsch (Vorschlag) |
  EN neu (Owner) | DE neu (Owner) | Kommentar (Owner) | Status), sorted by priority, then area. Default output:
  `external-docs/translation/` (private, not in git).
- `import <file.csv|file.xlsx>` → writes the owner columns "EN neu" / "DE neu" into the XML files, checks the
  placeholders, prints a diff; `--dry-run` only prints.
