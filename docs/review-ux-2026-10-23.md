# OnPath – UX logic review (2026-10-23, read-only, main @ d05c1f2)

Paths are relative to `app/src/main/java/com/onpath/app/`. Wording is not covered here (see text-review.md).

## 1. Logic problems (most important first)

1. **Cancel takes back the wrong change.** Steps: plan a route and add some points, then change the activity or the
   T level. The route is calculated again and is slow, so "Cancel" shows. Tap Cancel. Result: the last *point* edit is
   undone (a point disappears or a deleted one comes back), and the activity stays changed. The same happens with
   Cancel in "This route is very long" after an activity change, and when newer routing data starts a recalculation.
   During a tour this changed plan is followed straight away (the `step()` path sets `planEditPending`).
   Why it matters: one tap silently changes the plan, and maybe the followed tour. It breaks the owner's rule that
   Cancel while routing means undo *this* change.
   Fix: let Cancel undo only when the calculation came from a point edit. After an activity or T level change, Cancel
   should restore the previous activity and route. In every other case, Cancel leaves the plan unrouted.
   `ui/AppViewModel.kt:2016-2021` (cancelRouting), `:1983-1993` (answerLongRoute), `ui/PlanStatus.kt:22`; triggers
   `:1399-1410`, `:490`, `:3243`.

2. **Arrival skips the bus / car / lift summary.** Steps: take a bus during a tour, walk on, arrive, then tap "Save" in
   "You have arrived – end tour?". The tour is saved as recorded without the four choices. "End" in Plan would have
   shown them (core feature C12). The *Unfinished tour* dialog's "Save tour" also skips them, and it has no Delete
   (End tour is always Cancel · Delete · Save). Afterwards there is no "Tour saved" summary either, only a message.
   Why it matters: there are three ways to end a tour, and each behaves differently.
   Fix: send arrival Save and unfinished-tour Save through `askEndTour()`, which runs the ride check and shows the
   summary. Give the unfinished dialog Continue · Delete · Save.
   `ui/MapScreen.kt:196`, `ui/AppViewModel.kt:2743` vs `:2752`, `ui/Screens.kt:440-448`, `ui/AppViewModel.kt:2913`.

3. **Changing the activity during a tour: two different rules.** In Navigate, tapping the activity icon opens the
   check-and-switch sheet ("✓ fits / ⚠ …", then Take new route / Keep). In Plan during the same tour, the activity
   chip in the plan sheet opens the plain picker with no check and no question. Its new route only becomes the
   followed one at the next "Continue", silently. Until then, Plan shows "MTB" while Navigate still guides as "Hike".
   Why it matters: the owner said "a wrong activity is a disaster", and the safer path is the harder one to reach.
   Fix: see Question 1.
   `ui/MapScreen.kt:181-186`, `ui/AppViewModel.kt:1399-1402` + `:2555-2568`, vs `ui/NavigateScreen.kt:550`.

4. **After following a track during a tour, the plan cannot be followed again.** Steps: tour following a plan → ☰ My
   routes → open a recorded track → "Follow this track" → close it. "Continue" keeps following the track
   (`followIsTrack` blocks it), and plan edits are ignored. Nothing gets back to the plan until the tour ends. In Plan,
   both lines are drawn blue (`trackLook` only greys an *edited plan*), so it is unclear which one is followed. The same
   happens before a tour: with a track shown, Start navigation follows the track and the plan comes back underneath.
   Why it matters: a dead end, and two blue lines contradict "what Plan shows = what Navigate follows".
   Fix: see Question 7. At the least, draw the plan grey while a track is followed.
   `ui/AppViewModel.kt:2555-2568`, `:2831-2837`, `:2577-2585`, `ui/MapScreen.kt:302-306`.

5. **A track starts navigation with an activity you cannot see or change.** The track panel ("Start navigation" /
   "Follow this track") has no activity chip and does not name the activity. Opening a recorded bike tour does not
   take over its activity either (only planned routes do). To change it you must close the track, change the chip in
   the plan sheet, and open the track again.
   Fix: show the activity chip in the track panel and name it on the button ("Start navigation · Hike"). Take the
   activity from a recorded tour when it is opened.
   `ui/Panels.kt:164-170`, `ui/AppViewModel.kt:2958-2968` (tracks keep the current activity).

6. **"Maps only on Wi-Fi": no way to load once over mobile data.** Map areas only wait for Wi-Fi when the setting is
   on (`allowed()`). The strip's mobile-data question (Only on Wi-Fi / Load now) is only built when the setting is
   *off*, so it can never appear. With the setting on, the loading modal says "will load when you're on Wi-Fi" and
   offers only Cancel, and the strip offers only ×.
   Why it matters: on a trail without Wi-Fi this is a dead end. The user has to find Settings → Offline maps, switch
   the setting off and switch it back on later.
   Fix: when areas wait for Wi-Fi, show "Load now (mobile data)" in the modal and in the strip (`approveMobile`).
   `cells/MapCells.kt:722`, `ui/CellCard.kt:165`, `ui/MapLoad.kt:44,290-296`, `ui/BackgroundDownloads.kt:253`.

7. **Ending route guidance during a tour: "Clear route" is greyed out, but deleting points one by one does the same
   job.** During a tour, sheet ⋯ → Clear route is disabled. Tapping ✕ on every point in the Points list ends the route
   guidance anyway (owner A12, Undo restores it).
   Fix: see Question 2. `ui/PlanPanel.kt:451`, `ui/RouteRules.kt:50`, `ui/AppViewModel.kt:1489-1494`.

8. **The same word does different things, and a wrong insertion has no direct fix.** The map point menu "Start here"
   removes the points before it. The search card's "As start" moves the point to the front and keeps all others. The
   search card has "As destination"; the map point menu has no "make destination" since "End here" was removed. A
   held point that the smart insertion puts in the middle (you meant a new goal) can now only be fixed with Undo or by
   dragging ≡ in the full sheet. The code comment still says "fixed in the point menu (End route here)".
   Fix: see Question 3. `ui/AppViewModel.kt:1608-1611`, `:1783-1797`, `:1507`, `ui/MapGestures.kt:99-105`.

9. **A tap outside "This route is very long" undoes your last change.** `onDismissRequest = onCancel`, and Cancel
   means Undo. A stray tap or Back silently removes the point you just set.
   Fix: make the dialog stay until a button is tapped (like "Route back to the start?"). `ui/TourBar.kt:186`.

10. **First start stacks several things at once.** On a fresh phone, the location permission request, "Restore your
    tours?" (any time the database is empty) and the "Loading the map for your area" modal (a Dialog that cannot be
    dismissed) can all be open together. One covers the other, and the strip's "Allow location" sits underneath.
    Fix: show the restore offer only after the loading modal has closed, or before location is asked.
    `MainActivity.kt:182-186`, `ui/AppViewModel.kt:3068-3076`, `ui/MapScreen.kt:333`.

11. **Messages cover the blue strip.** The general message bar ("…OK") sits at 70 dp from the top. The blue strip,
    which carries the map questions (Try again, Allow location), sits at 68 dp. Messages stay until OK, so the strip's
    buttons are hidden until then. The overview hint and the menus already move down for the strip; the message bar
    does not.
    Fix: place the message bar below the strip while it shows (`vm.backgroundStripShown`). `MainActivity.kt:279-283`
    vs `ui/MapScreen.kt:287`.

12. **An unsaved plan can be lost by "End tour → Save".** After any End tour, the plan leaves the map, saved or not
    (owner 2026-10-22). Undo brings it back, but the undo history exists only in memory, so it is gone once Android
    closes the app. Nothing tells the user this. The "Clear route from map" button in "Tour saved" never appears,
    because the plan is already cleared before the dialog shows.
    Fix: see Question 4. `ui/AppViewModel.kt:1186-1188`, `ui/PlanState.kt:9`, `MainActivity.kt:326`.

13. **Undo and Redo are in different places.** Undo is a map button above the sheet; Redo is in sheet ⋯. The layout
    rule in `docs/ux-two-modes.md` puts both in the sheet's first line.
    Fix: see Question 8. `ui/MapScreen.kt:100`, `ui/PlanPanel.kt:444`.

14. **During a tour, the button back to Navigate no longer names the activity.** Owner rule: "Continue navigation ·
    Trekking bike". The tour row shows only "Continue", and the named primary button is hidden during a tour.
    Fix: label it "Continue · Hike", or keep the named primary button and drop the duplicate in the tour row.
    `ui/TourBar.kt:141-145`, `ui/PlanPanel.kt:288`.

## 2. Questions for the owner

1. **Changing the activity in Plan during a tour.** In Navigate, tapping the activity icon checks the rest of the
   route for each activity and asks "Take new route / Keep". In Plan during the same tour, the activity chip changes
   it without a check or a question, and the next "Continue" quietly follows the new route. Which should it be?
   (A) Plan opens the same check-and-switch sheet as Navigate · (B) the chip is greyed out during a tour, change it in
   Navigate · (C) keep it as is (it counts as a plan edit).

2. **"Clear route" during a tour.** It is greyed out today, but deleting every point in the Points list already ends
   the route guidance (your decision A12: the tour keeps recording, Undo brings it back). Should Clear route do the
   same? (A) Yes, enable it during a tour, with the same effect · (B) No, and the last point in the list cannot be
   deleted either · (C) Keep as is.

3. **"Start here" / "As destination".** Holding a map point → "Start here" removes the points before it. The search
   card's "As start" moves the place to the front and keeps all points. Only the search card can make something the
   destination ("End here" left the map menu on 2026-10-22). A held point that lands in the middle by mistake can now
   only be fixed with Undo or by dragging it in the list. (A) Map menu gets "Make destination" (moves it to the end,
   keeps all), and "Start here" also just moves · (B) Map menu stays as is; the search card behaves like the map menu
   · (C) Leave both as they are.

4. **Unsaved plan when a tour ends.** After End tour (Save or Delete), the plan leaves the map. If it was never saved,
   only Undo brings it back, and only until Android closes the app. (A) Save it automatically to My routes ("Plan 23
   Oct") before clearing · (B) Ask once: "Keep the plan? Save / Discard" · (C) Keep as is.

5. **Ride summary at arrival.** When a bus, car or lift was detected, "End" in Plan shows the summary with four
   choices, but "Save" in "You have arrived – end tour?" saves the tour as recorded (Edit rides works later). Should
   arrival show the summary too? (A) Yes, the same summary after Save · (B) No, keep arrival short.

6. **"Maps only on Wi-Fi" in the field.** With this setting on, a map you are waiting for just says "will load on
   Wi-Fi". There is no button to load it once over mobile data (the "Load now" question only exists when the setting
   is off, so it never shows). (A) Add "Load now (mobile data)" to the modal and the blue strip · (B) Keep it strict –
   change the setting to load.

7. **Following a track, then the plan again.** During a tour you can open a saved track and tap "Follow this track".
   After that, "Continue" and plan edits never go back to the plan until the tour ends, and both lines are drawn blue.
   (A) "Continue" always follows what the plan sheet shows (to follow a track, use its own button again) · (B) Add
   "Follow the plan again" to sheet ⋯ during a tour · (C) Keep as is, but draw the plan grey while a track is followed.

8. **Undo / Redo placement.** Undo is a round map button; Redo is in the sheet's ⋯ menu. (A) Both as map buttons
   · (B) Both in the sheet's first line, as the layout rule says · (C) Keep as is.

## 3. Fine as is

I checked these flows and found them consistent: holds only edit in Plan, and Navigate never adds or moves anything. Menus have no Cancel button and close with a tap outside or Back. The first-hold menu (Start here / Go here, greyed with the reason) and the POI menu match the spec. The point menu acts on the point by position. Disabled items stay visible. Navigate draws only the route line, and Plan draws the points during a tour too. Slide to plan is the only way out of Navigate. Off-route, "Route back to the start?", the activity switch sheet and the Delete confirmations stay until answered. End tour is Cancel · Delete · Save, with Delete asking again and going to the recycle bin. Planned routes are blocked from loading during a tour ("Can be loaded after the tour"). "Replace current plan?" offers Save first / Replace. The tour being recorded cannot be deleted or have its rides edited. The plan sheet has three steps with one primary button and the tour controls on top during a tour. Unreachable points (red line + Show) and route warnings (amber line → list of spots) work. There is one loading modal for your own area (Cancel = stop) and one blue strip for background loads plus a Navigate chip, both opening the same details with "Cancel all". Clear all is blocked during a tour. Updates are quiet during a tour, with "After the tour / Install now". Search, the place card and shared places go into Plan.
